# Установка и поддерживаемые платформы

Перед первой миграцией закройте прежние окна Spotify/SoundCloud/Telegram/VPN/tthings.
Telegram использует прежнюю базу авторизации: два клиента не должны открывать
её одновременно. Установка не удаляет её и не запускает клиента сама.

| Платформа | Состав | Состояние |
|---|---|---|
| Linux x86_64 / SteamOS | ttools и пять приложений, включая SoundCloud | SoundCloud preview; комплектный локальный runtime Spotify рассчитан на glibc 2.43 |
| macOS ARM64 / x86_64 | ttools, Spotify, TVPN, tthings | Preview; SoundCloud и Telegram не входят, реальные native smoke/туннель не подтверждены |
| Windows x86_64 | ttools, Spotify, Telegram, TVPN, tthings | SoundCloud не входит; Telegram preview-кандидат, ручной smoke, звук и туннель не подтверждены |

Linux Telegram: CPython 3.14, glibc >=2.28, tmux >=3.4, ffmpeg/ffprobe с
libopus/PulseAudio, ffplay, kdialog, pactl, системный `/usr/bin/python3` с
PyGObject/GTK3. Для SIXEL нужен соответствующий терминал и tmux; DOTS-режим
доступен в самом Telegram. PipeWire Pulse/PulseAudio и микрофон нужны голосовым,
но установщик микрофон не включает. На SteamOS эти зависимости проверяются;
read-only root не отключается. В Debian/Ubuntu bootstrap может поставить пакеты
через apt с обычным запросом sudo. На прочих дистрибутивах недостающие пакеты
нужно предоставить системным пакетным менеджером.

Для Linux VPN нужны bash, curl, iproute2, flock, sudo/visudo. Правила и backend
устанавливаются штатным установщиком TVPN с правами администратора; VPN при
установке не подключается. На macOS его native installer готовит Tunnelblick,
на Windows — официальный OpenVPN и локальную группу. Windows может потребовать
повторного входа пользователя для применения прав.

SoundCloud работает на Linux x86_64. Для демо системные аудиозависимости не нужны;
для живого воспроизведения установите FFmpeg и SDL2 и подключите рабочий аудиовыход.

Обычные окна tthings требуют Tk. Выделение областей на Linux — Qt6/QML и KWin;
их наличие не требуется для терминального меню. Внешние 41 проекты tthings
в комплект не входят и автоматически не устанавливаются.

## Локальный архив без GitHub

Распакуйте ZIP своей ОС. `Install-ttools.sh` / `Install-ttools.command` /
`Install-ttools.cmd` готовит CPython 3.14 и вызывает install-only. macOS устанавливает неполный комплект без Telegram и SoundCloud; Windows — без SoundCloud, а поддержка Telegram зависит от выбранного preview.

Если CPython 3.14 уже готов, откройте терминал в папке `ttools`:

```sh
python3 installer.py
```

Для полной Linux-установки используйте CPython 3.14. На macOS/Windows с
неподдерживаемыми компонентами нужен явный `--allow-partial`:

```sh
python3 installer.py --allow-partial
```

Windows-команда Python может называться `py -3.14` вместо `python3`.
Установка из source-архива может скачивать Python-зависимости Spotify и
windows-curses/psutil. Локальная поставка `--handoff` содержит Linux native
Spotify и offline-wheelhouse Telegram; архивы для других ОС их не используют.

Проверить состав до установки:

```sh
python3 installer.py --plan
python3 installer.py --plan --allow-partial
```

Только отдельные компоненты (не полный комплект):

```sh
python3 installer.py --components tthings
```

Для проверки в отдельном каталоге, без ярлыков и системного VPN-backend:

```sh
python3 installer.py --prefix '/tmp/Тест ttools' --defer-system --no-shortcuts
```

Этот режим не делает VPN готовым: `complete=false`. Он нужен тестам и
подготовке пользовательских файлов. Полная установка не использует этот флаг.

## Windows: диагностика и журнал установщика

Извлеките ZIP полностью. Безопасная диагностика запускается так:

```powershell
powershell.exe -NoProfile -File .\ttools\scripts\Diagnose-TTools.ps1
```

Она проверяет запуск CPython 3.14, видимость команд WinGet, App Installer и
WinGet alias. Диагностика ничего не устанавливает и не меняет; домашние пути в
выводе маскируются.

Для установки из ZIP с подробным журналом:

```powershell
& .\ttools\Install-ttools.cmd -Preview -LogPath "$env:LOCALAPPDATA\ttools-install.log"
```

Для официального PowerShell-установщика команда выглядит так:

```powershell
& .\install.ps1 -Preview -LogPath "$env:LOCALAPPDATA\ttools-install.log"
```

Журнал дополняется при повторном запуске. Перед отправкой журнала проверьте
строки с путями установки.

## Данные и обновления

Префикс по умолчанию:
- Linux: `${XDG_DATA_HOME:-~/.local/share}/ttools-suite`;
- macOS: `~/Library/Application Support/ttools`;
- Windows: `%LOCALAPPDATA%/ttools`.

В `state.json` записана активная версия. Релизы находятся в `releases/`.
Новая версия получает новый каталог; работающая версия не перезаписывается.
Пользовательские данные приложений хранятся вне каталога релиза.

Лаунчер проверяет канал релизов при запуске: не чаще одного раза в шесть часов,
а после сетевой ошибки повторяет попытку через 15 минут. На macOS он показывает
доступную версию и спрашивает, устанавливать ли её; пустой ответ пропускает
обновление до следующей проверки. На остальных платформах включено автоматическое
обновление. Если сеть недоступна,
установленная версия всё равно запускается. Проверка читает публичную ленту
релизов GitHub и скачивает манифест и архив по HTTPS; содержимое сверяется по
SHA-256 до установки. Релизы хранятся отдельно от исходников и страницы README.

Отключить проверку и предложение обновления на один запуск: `TTOOLS_AUTOUPDATE=0 ttools`
(на Unix). Принудительно проверить и установить обновление: `ttools --update`.
При запуске из исходников без установленного suite эти флаги управления
не предоставляются.

Удаление пользовательского префикса и ярлыков не удаляет авторизацию приложений.
Системный VPN-backend и sudoers следует удалять штатными средствами TVPN:
простое удаление папки ttools не является удалением защищённого VPN-компонента.

## Нативный Telegram для Windows — preview

В следующем предварительном комплекте Windows x64 Telegram устанавливается вместе с остальными приложениями. WSL, tmux и отдельная установка Python не нужны. Требуются Windows 10/11 x64 и Windows Terminal 1.22+ с SIXEL; терминал устанавливается отдельно.

Поставка `2026.11.18.7-win1` ещё не прошла проверку на настоящей Windows. Автоматические проверки на Linux не подтверждают работу DLL, микрофона, clipboard и SIXEL на Windows. В стабильный канал компонент пока не включён.

Установку выполняет встроенный Python, приложение запускается внутри терминала лаунчера. ttools доставляет новые версии в составе проверенного комплекта; перед переключением Telegram получает адресный запрос на штатное завершение. Данные сохраняются отдельно в `%LOCALAPPDATA%\ttools\ttelegram-data`. Для запуска тестового интерфейса без аккаунта предусмотрен `--demo`.

[Контракт интеграции и Windows smoke test](../components/ttelegram/windows-native/HANDOFF.md). Исходники входят в репозиторий; офлайн-зависимости — в отдельный архив с закреплённым SHA-256, который проверяется при сборке.

## Фоны лаунчера в кандидате

`--background light_bloom` выбирает основную сцену; меньшая вторая сцена подбирается случайно. N меняет сочетание, Space ставит движение на паузу. `--no-motion` запускает неподвижный фон, `--low-power` ограничивает размер до 96×32 и частоту до 4 кадров/с. Выбор через CLI действует на этот запуск; постоянного файла настроек анимации пока нет.

Прозрачность сохраняет стандартный фон терминала. Профиль Konsole и других терминалов не переключается; фон и прозрачность остаются такими, как их настроил пользователь. Дополнительные графические окна для работы лаунчера не создаются.

## macOS: CERTIFICATE_VERIFY_FAILED

Если curl скачал скрипт, но Python сообщил `unable to get local issuer certificate`, у этого Python может отсутствовать собственный набор CA. Кандидат установщика и загрузчик обновлений дополнительно используют системный `/etc/ssl/cert.pem` на macOS. Проверка сертификата и имени хоста остаётся включённой; явные пользовательские SSL_CERT_FILE / SSL_CERT_DIR не заменяются. Системные файлы и настройки Python не изменяются.

Для уже опубликованного установщика можно указать системный набор на один запуск:

```sh
curl -fsSL https://raw.githubusercontent.com/user9x21imi/ttools/main/install.sh | SSL_CERT_FILE=/etc/ssl/cert.pem sh -s -- --preview --allow-partial
```

Это не отключает SSL-проверку. Если системного PEM нет или его CA не подходят вашей сети, для Python с python.org предусмотрен штатный `Install Certificates.command` в `/Applications/Python 3.x/`: [документация Python](https://docs.python.org/3.14/using/mac.html). Не используйте `curl -k`, CERT_NONE или глобальное отключение проверки HTTPS.
