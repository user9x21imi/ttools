# ttelegram — нативный Windows x64, 2026.11.18.7-win1

**Статус: предварительная версия для интеграции и проверки на Windows.**
Это нативный порт, без WSL, Linux-бинарников и tmux. Полностью проверенной рабочей Windows-версией пока не объявляется: у автора сборки есть Linux, но нет Windows-хоста. Перед включением в стабильный канал лаунчера нужен Windows smoke test ниже. Не подменять этим архивом работающую Linux-установку.

## Что передавать агенту

Весь этот каталог или ZIP `ttelegram-windows-native-2026.11.18.7-win1.zip`. Здесь исходники (`source/`), готовый Python 3.14.6 Windows x64 (`bootstrap/`), Windows wheels (`wheels/`), офлайн-установщик, тесты, manifests и лицензии. Исходный python-telegram 2.0.0 Windows не поддерживает; здесь отдельный проверяемый pure-Python fork `2.0.0+ttnative.1`, использующий нативный tdjson 1.8.66. Его исходники находятся в `source/vendor/python-telegram/`; `rebuild_transport.py` пересобирает wheel. Доработанный `tg/views.py` и diff сохранены в `source/vendor/`, до применения проверяются исходный и конечный SHA-256.

База TDLib, переписка, авторизация, пользовательские конфигурации, записи голоса, кеши и журналы в поставку не входят.

## Требования и запуск

Windows 10/11 x64, Windows Terminal 1.22+ с SIXEL. Для голоса — доступ приложения к микрофону в настройках Windows. Python, WSL, tmux, ffmpeg в PATH и права администратора не нужны. Windows Terminal устанавливается отдельно. Архив распаковать целиком, не запускать файлы внутри ZIP.

- `install.cmd` — офлайн install-only в `%LOCALAPPDATA%\ttools\ttelegram`, без запуска интерфейса и без входа.
- `run.cmd` — новое окно/вкладка Windows Terminal.
- `run.cmd --demo` — искусственный аккаунт без реальных отправок и без микрофона.
- `check.cmd` — проверка установленного runtime, импортов, TDLib и FFmpeg; микрофон не открывает.
- Для другого пути: `install.cmd --prefix "D:\Программы с пробелами\Telegram"`, тот же `--prefix` передавать run/check.
- `run.cmd --in-terminal` — запуск внутри уже открытого совместимого терминала.

Запуск из уже установленного каталога: `${PREFIX}\ttelegram.cmd`. Этот файл не устанавливает зависимости при запуске.

## Точный argv для лаунчера

Значения `${BUNDLE}` и `${PREFIX}` подставляет лаунчер как пути, без shell-интерполяции. Каждый элемент — отдельный аргумент; не объединять в командную строку вручную.

Общий launcher trampoline указан в app.json: embedded Python не добавляет каталог скрипта в sys.path, поэтому используется `-c` + `runpy.run_path`. Исходный каталог передаётся отдельным аргументом. Все команды независимы от cwd и аккаунта `deck`.

Установка/обновление:
`[${BUNDLE}\bootstrap\python.exe, -c, <trampoline из app.json>, ${BUNDLE}\manage.py, install, --prefix, ${PREFIX}, --stop]`

Запуск/версия/проверка/остановка/откат:
`[${PREFIX}\bootstrap\python.exe, -c, <тот же trampoline>, ${PREFIX}\manage.py, launch|version|doctor|stop|rollback, --prefix, ${PREFIX}]`

Для безопасного теста добавить к launch `--demo`; для rollback при открытом клиенте добавить `--stop`. Ctrl+Q сохраняет выбранный чат и черновики и завершает приложение. stop использует файл запроса с токеном конкретного процесса и ждёт освобождения instance-lock; чужие процессы не завершает.

## Обновление и данные

Обновления применяет **ttools**, приложение не скачивает их по F8. Публичного релиза и HTTPS-манифеста пока нет: URL указаны null, локальная поставка готова. Не выдавать restart за автообновление. Для каждого нового выпуска лаунчер должен получить проверенный архив/его SHA-256, распаковать и вызвать install с новым BUNDLE. Встроенный files.json обнаруживает повреждение; подлинность внешнего архива должна проверяться по SHA из доверенного канала лаунчера.

Установка версионная: `versions/<version>`, сначала проверка всех поставляемых SHA, затем staging, doctor нативным интерпретатором и только потом атомарная смена current.json. При ошибке doctor активная версия не меняется. Повторная установка идемпотентна; предыдущая версия остаётся для rollback. manager.lock исключает параллельные изменения. Установщик требует штатного завершения открытого клиента; без --stop отказывает. Вход второго клиента блокируется account-instance.lock.

Данные отдельно: `%LOCALAPPDATA%\ttools\ttelegram-data` (TDLib, session.json, media.json, layout.json, logs). Временные медиа и голос используют также `%USERPROFILE%\.cache\ttelegram`; загрузки — Downloads. Эти каталоги не удаляются при обновлении. Для изолированной проверки задавать `TTELEGRAM_DATA_DIR` в отдельный каталог. Демо всегда использует отдельные временные настройки и fake backend.

## Интерфейс

Собственный VT backend выводит текст и SIXEL одним потоком; tmux/PDCurses не участвуют. Есть рамки, синий заголовок Telegram, список чатов, поле ввода, клавиши и мышь. Ctrl+L — чаты; Ctrl+O/F4 — настройки; F1 — подсказки; Ctrl+T — стикеры/GIF; Ctrl+U — файл; Ctrl+G — запись/остановка; P — старт/остановка прослушивания записанного; Enter — отправка; Esc — отмена записи; Ctrl+Q — выход. Голос отображается внутри поля сообщения, пройденная часть waveform белая. Микрофон и воспроизведение используют PortAudio, Opus/превью — bundled FFmpeg. Нативный выбор файла, текст/изображение/файлы из Win32 clipboard; оригинал отправляется собеседнику. Обычные изображения включены по умолчанию, DOTS выбирается в настройках.

Windows Terminal может перехватывать Ctrl+V своим действием paste: для изображения использовать Ctrl+B или кликабельную кнопку «Вставить» в поле ввода (читает Win32 clipboard напрямую). Перенос файлов зависит от того, вставляет ли терминал полный путь: гарантированный путь — кнопка «Файл»/Ctrl+U. Системные toast-уведомления Windows пока не реализованы. Анимации/Win32 API требуют проверки на реальном хосте.

## Реально проверено на Linux

- SHA-256 официального Python embedded x64 совпал с опубликованным python.org: `df901e84a896ff1ee720ad03377e0c8d8c2244fda79808aeeaff6316df1cb75c`.
- Офлайн pip resolution полного комплекта для CPython 3.14 / win_amd64: все зависимости присутствуют, Linux wheels нет.
- Восемь автоматических тестов: безопасная распаковка Windows wheels, нарушение SHA, пути с пробелами/кириллицей, install/reinstall/update/rollback, отказ staging doctor; VT клавиши/мышь и отсутствие перерисовки неизменённых строк; синтетическая тишина/тон → Opus, waveform и переключение прослушивания без аудиоустройства. **Windows-исполнение doctor в transaction-тесте заменено заглушкой.**
- PTY smoke общей VT/UI логики: открытие чата, вставка тестовой картинки с подписью, fake send, 100 progress updates без перерисовки истории, прокрутка, выход из настроек, возврат к списку чатов, сохранение черновика, Ctrl+Q. SIXEL действительно выведен. Это проверка потока, не визуальная сертификация Windows Terminal.
- Транспорт tdjson: getOption(version), async response, close на TDLib 1.8.66 Linux без авторизации. Windows DLL находится в комплекте, но здесь не исполнялась.

Команды: `python -m unittest discover -s tests -v`; POSIX-only UI smoke: `python tests/smoke_ui_pty.py` в окружении tg/Pillow. `manage.py verify` проверяет поставку. Результаты записаны в TEST-RESULTS.txt.

## Обязательно проверить агенту на Windows до stable

1. install.cmd и check.cmd от обычного пользователя, затем повторить в пути с пробелами/кириллицей. Установка не открывает UI/QR.
2. run.cmd --demo: чат, клавиши, мышь, вставка, скролл, настройки, смена размера, закрытие и повторное открытие. Отдельно смотреть изображения после 30 циклов скролла/настроек: без белой заливки, наложений и нарастающей очереди.
3. На разрешённом тестовом аккаунте: QR, 2FA, повтор после закрытой авторизации, список чатов; файлы/картинка с подписью/стикер/GIF; просмотр фото целиком. Демо не заменяет сетевые проверки.
4. С разрешением пользователя: Ctrl+G, сигнал только с микрофона, стоп Ctrl+G, P/P, белый прогресс, Enter, восстановление черновика.
5. Запущенный клиент → manage stop → version; обновление второй версией → rollback; сохранность авторизации/чата/черновика. Не включать в stable до прохождения.
