# Задание будущему агенту: терминальный клиент SoundCloud

Референс: https://github.com/user9x21imi/tspotify

Версия кода, на которой основано описание: https://github.com/user9x21imi/tspotify/tree/3d22a81

Ниже — готовое сообщение для передачи агенту. Это описание референса и требований, а не утверждение, что Spotify-реализацию нужно целиком переносить в SoundCloud.

---

Ты будешь разрабатывать отдельный терминальный клиент SoundCloud с похожим интерфейсом и поведением tspotify.

**Сейчас разрешено только изучить описание и исходники, кратко подтвердить понимание и ждать. Не начинай разработку, установку зависимостей, авторизацию, воспроизведение или публикацию. Пользователь следующим сообщением объяснит свою особую фишку SoundCloud-клиента. Не придумывай её и не принимай архитектурных решений, которые помешают её добавить.**

## 1. Что представляет собой референс

`tspotify` — полноценное приложение с терминальным интерфейсом. Основной интерфейс написан на Python/curses. Аудио воспроизводит отдельный принадлежащий клиенту движок Rust/librespot, подготовленный на основе spotify_player. Официальное приложение Spotify для встроенного воспроизведения не требуется.

Это три разные обязанности: интерфейс, интеграция с сервисом, локальное воспроизведение. В SoundCloud их тоже нужно отделить. Spotify Connect, его OAuth, клиентские ID, Premium и Rust-патчи Spotify не являются реализацией SoundCloud.

Для чтения кода:

- `src/tspotify/cli.py` — запуск, параметры, авторизация, диагностика, завершение.
- `src/tspotify/ui.py` — панели, клавиши, мышь, поиск, временная поисковая раскладка, полноэкранный плеер.
- `src/tspotify/api.py` — запросы к сервису, метаданные, коллекции, состояние, кэш, обработка ошибок.
- `src/tspotify/backend.py`, `engine/local_control.rs`, `scripts/prepare_native_engine.py` — встроенное воспроизведение, локальные команды, подготовка движка.
- `src/tspotify/art.py` — загрузка, кэш и преобразование обложек.
- `src/tspotify/audio.py` — получение звука клиента и расчёт спектра.
- `src/tspotify/session.py`, `paths.py` — настройки, сессия, приватные пути.
- `src/tspotify/control.py`, `shortcuts.py` — управление работающим экземпляром и системные медиаклавиши.
- `src/tspotify/updates.py`, `managed.py`, `scripts/install_ttools.py` — обновления и интеграция с общим лаунчером ttools.
- `tests/`, `scripts/smoke_terminal.py` — проверки логики и реального терминала без слышимого звука.

README местами может отставать от поведения программы. Для конкретной функции проверяй соответствующий код и тесты. Наличие кода или зелёного теста не доказывает исправность всех сценариев на каждой ОС.

## 2. Обычный интерфейс

По умолчанию панели сверху вниз: поиск, «Сейчас играет», спектр, библиотека. Ниже — громкость, статус и подписанные элементы управления.

Панели отделены тонкими рамками. Название трека, исполнитель, альбом, время, выбранная строка и ошибки различаются цветом и насыщенностью. Фон должен наследовать фон терминала; прозрачность зависит от самого терминала и его профиля.

В SoundCloud сохрани этот дизайн-код, добавив сдержанные оранжевые акценты. Не перекрашивай всё одним цветом: сохраняй читаемую иерархию текста.

Обложка — цветное изображение из точек/Braille, а не случайный набор ASCII-символов. Большая обложка должна оставаться узнаваемой. В списках нужны мини-обложки. Обычный Unicode monospace должен работать без обязательного Nerd Font; предусмотрен ASCII fallback. Не меняй системные шрифты пользователя.

Стартовый логотип должен быть узнаваемым, точечным и коротким — около двух секунд, с возможностью отключения. Для SoundCloud нужен свой логотип, а не перекрашенный знак Spotify. Не добавляй эту паузу к каждой операции.

## 3. Поиск по мере ввода

Пользователь нажимает поле поиска или клавишу поиска и начинает писать. Результаты появляются без обязательного Enter. Дописывание запроса уточняет результаты: например, короткое имя сначала даёт широкий список, полное имя — более точные совпадения.

Из уже загруженной библиотеки можно показывать подходящие записи сразу. Результаты сервиса приходят асинхронно и дополняют их. Небольшое объединение быстрых нажатий нужно для сетевых запросов, но не для задержки локального фильтра.

Карточка трека содержит мини-обложку, название, исполнителя, альбом/релиз при наличии и длительность. Также показываются подходящие исполнители, альбомы и плейлисты, если сервис действительно предоставляет такие результаты. Тип результата должен быть понятен.

Запоздалый ответ для старого текста не заменяет новый запрос. Дополнение результатов не должно переставлять выбранную пользователем строку или запускать другой трек под прежней позицией мыши.

## 4. Временная поисковая раскладка

Это важная часть поведения:

1. При фокусе поиска поле остаётся сверху.
2. Под ним разворачивается большой список результатов. Панель временно называется «Список» вместо «Библиотека».
3. «Сейчас играет» и спектр перемещаются максимально вниз и становятся компактными.
4. Пока пользователь переходит из ввода к результатам, раскладка остаётся поисковой.
5. При возврате фокуса к плееру/спектру, по Esc или F3 восстанавливается обычная пользовательская раскладка.
6. Это временный режим: он не перезаписывает сохранённый порядок и размеры панелей.
7. После выхода поздний ответ поиска не должен снова раскрывать поисковый режим.

Режим должен работать мышью и клавиатурой, при разных размерах терминала, без наложения прогресса/спектра на список.

## 5. Поиск внутри коллекции

Если открыт альбом или плейлист, обычная строка поиска и `/` фильтруют его загруженные треки локально. Поиск учитывает название и исполнителя; альбом — когда эти данные доступны.

Область поиска должна быть написана явно: «Весь SoundCloud», «В этом плейлисте», «В этом альбоме». Не повторяй неоднозначный общий заголовок «Поиск», по которому непонятен охват.

F2 и видимая кликабельная кнопка переключают на поиск по всему сервису. Очистка локальной строки/Esc возвращают полный список. Возврат из общего поиска должен сохранять возможность вернуться к открытой коллекции.

Запуск найденного трека сохраняет исходный порядок коллекции. Фильтр не превращает очередь воспроизведения в список только совпавших строк. Поздний ответ общего поиска не заменяет локальные результаты.

## 6. Библиотека, плеер и навигация

Enter или одинарный щелчок открывает коллекцию; выбор её трека запускает именно этот трек. Назад возвращает предыдущий список. Колесо прокручивает, стрелки выбирают строку. Цифры переключают разделы.

В Spotify-референсе есть плейлисты, любимые треки, альбомы, недавнее и несколько разделов миксов/рекомендаций. Для SoundCloud состав разделов нужно определить после проверки его возможностей и получения пользовательской особой фишки. Не создавай фиктивные рекомендации или неработающие вкладки ради сходства.

Текущий трек показывает реальное состояние: обложку, название, автора, релиз, позицию, длительность и избранное. Кнопки play/pause, предыдущий/следующий, громкость, mute, избранное и доступные режимы очереди должны иметь подписи и работать мышью.

F3, кнопка разворота или обложка открывают большой плеер: подробная точечная обложка, данные трека, прогресс и плавный точечный визуализатор под ними. F3/Esc возвращают назад. Перемотка должна поддерживать захват и ведение мышью, локальное предварительное отображение и корректную конечную позицию.

`L` открывает настройку расположения панелей. Пользователь может менять их порядок, сторону обложки и видимость спектра. Обычная раскладка сохраняется отдельно от временного поиска.

## 7. Управление

Сохрани понятную раскладку, если возможности SoundCloud позволяют:

- F7 — предыдущий; F8 — play/pause; F9 — следующий.
- F10 — mute; F11 — тише; F12 — громче.
- Space — play/pause; `n`/`p` — следующий/предыдущий; `+`/`-` — громкость; `m` — mute.
- `f` — добавить/убрать избранное, если сервис поддерживает это действие.
- `/` — поиск в текущем контексте; F2 — общий поиск.
- Tab/стрелка вниз — переход от ввода к результатам.
- F3 — большой плеер; `L` — раскладка; `?`/F1 — справка.
- Ctrl+Q — штатный выход из любого режима, включая поиск и справку.

Проверяй не только F-коды терминала, но и аппаратные Media Play/Pause/Next/Previous/Volume. Сфокусированный терминал сам по себе не гарантирует, что ОС не отдаст Media Play браузеру с YouTube. Системное управление должно быть явно направлено клиенту; временно занятые сочетания восстанавливаются при выходе. Для каждой ОС нужно проверить её механизм, а не объявлять KDE-реализацию универсальной.

## 8. Скорость и достоверность состояния

В интерфейсе не должно быть блокирующих сетевых запросов. Аудиокоманды, поиск, метаданные и обложки не должны ждать друг друга в одной очереди.

Громкость, пауза и перемотка по возможности выполняются локальным аудиодвижком. Не отправляй сетевой REST-запрос на каждое нажатие громкости. Кэшируй метаданные и обложки с ограничением памяти, загружай соседние обложки заранее. Рассмотри предзагрузку следующего аудио, если выбранный способ воспроизведения это поддерживает.

Повторные нажатия не теряются. Новый выбор может отменить ожидание старого. Принятая команда не равна реально начавшемуся воспроизведению: это разные состояния. Можно сразу показать выбранный трек с честным статусом загрузки, но нельзя объявлять успех без подтверждения.

У состояния должен быть один авторитетный источник и идентификатор трека/поколение команды. Запоздалые ответы, старые подтверждения и кэш не возвращают предыдущую песню. Обложка, название, время и статус должны относиться к одной записи. Внизу нельзя оставлять вечное «Воспроизводится: старая песня».

Не запускай одновременно конкурирующие менеджеры очереди и скрытый механизм, который переносит назад старую сессию. Не перезапускай живой аудиодвижок из-за единственного тайм-аута метаданных.

Прогресс использует непрерывные локальные часы. Старый опрос не дёргает его назад после перемотки. Неизвестная длительность не считается равной одной миллисекунде и не рисует полную полосу.

Измеряй отдельно: отклик интерфейса, доставку команды, готовность аудио, холодную/тёплую загрузку обложки. Не выдавай миллисекундное подтверждение команды за мгновенное начало звука.

## 9. Аудио, сессия и авторизация

Спектр отражает только звук этого клиента, а не общий системный микс и не случайную анимацию. Предпочтителен анализ собственного PCM-потока; если используется захват, он должен быть изолирован от YouTube, уведомлений и других приложений. Нужны реальный FFT и плавное затухание/нарастание.

Сохраняются пользовательская громкость, трек, позиция и контекст коллекции. Восстановление — на паузе. Временная тестовая/стартовая громкость 0 не перезаписывает пользовательское значение. Настройка должна применяться и после фактической активации аудио: некоторые движки игнорируют команду, отправленную слишком рано.

До реализации проверь актуальную официальную документацию SoundCloud: доступ к API, авторизацию, refresh, доступные потоки, поиск и ограничения. Не переносить OAuth Spotify и не обещать QR, синхронизацию с официальным клиентом, рекомендации или произвольное воспроизведение, пока доступность не подтверждена. QR, если возможен, является способом открыть подтверждённый браузерный сценарий, а не обходом входа.

Токены хранятся приватно, вне репозитория и поставки. Нельзя извлекать чужие cookies или обещать автоматический вход только потому, что пользователь авторизован в официальной программе. Сетевой тайм-аут не должен ошибочно предлагать повторную авторизацию.

## 10. Поставка и проверки после разрешения на разработку

Нужен самостоятельный клиент, не требующий установки официального SoundCloud-приложения. Зависимости воспроизведения должны входить в пакет или явно подготавливаться установщиком до первого запуска. Не скачивай неожиданно большой движок при первом нажатии play.

Целевые ОС: Linux/SteamOS, macOS Apple Silicon/Intel, Windows Terminal/PowerShell. Для каждой отдельно подтвердить реальную сборку и работу. Linux ZIP не является поддержкой macOS. Не обещай одинаковую проверенность платформ.

Установка — простой пользовательский путь, без root там, где он не нужен. Для ttools предусмотреть точные переносимые argv запуска/версии/остановки/обновления, сохранение данных, блокировку параллельного обновления и откат. Один владелец обновлений: сам клиент после Yes/No либо ttools, но не оба одновременно.

Публиковать только существующие файлы, действительные ссылки и проверенные SHA-256. Кнопки загрузки не должны вести в пустоту.

Проверять реальные сценарии: вход, выбор правильного трека, смену и очередь, скорость громкости, быстрые повторы клавиш, мышь, фильтры, временную раскладку, потерю сети, закрытие и восстановление сессии. Официальный клиент/браузер не должны получать команды вместо нашего плеера. При закрытии завершаются только принадлежащие клиенту процессы.

Автоматические проверки выполняются без звука либо с гарантированной нулевой громкостью/изолированным выходом. Они не должны перехватывать управление уже работающим пользовательским экземпляром, менять обычную сессию или оставлять музыку после завершения. Нужны сценарии и реального терминала, а не только моки. Пиши отдельно, что проверено реально и что остаётся предположением.
