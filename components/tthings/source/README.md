# tthings 0.7.2

Текущий каталог: **200 эффектов + 19 системных инструментов = 219 режимов**. Ещё 41 запись — внешние проекты, в это число не входят. Подсчёт выполнен по BUILTINS, SYSTEM_TOOLS и ENTRIES.

Единый терминальный лаунчер красивых анимаций и полезных системных инструментов. Интерфейс на русском,
поиск, категории, предпросмотр, избранное, случайный выбор, отдельные окна
и выделение области рабочего стола. Работает без sudo и изменения системного раздела SteamOS.

## Быстрый запуск на этой машине

```sh
~/.local/bin/tthings
```

Если установка ещё не запускалась, в папке исходников:

```sh
sh install.sh
```

Это одна команда: она создаёт автономный zipapp в `~/.local/bin`, ярлыки
и настройку сочетания клавиш. Исходный вариант требует Python 3.10+;
оконный режим дополнительно требует Tk. На текущей SteamOS оба модуля доступны.
Установленный файл не зависит от сохранности папки исходников.

## Установка готовой сборки — одна команда или один установщик

Распакуйте архив **для своей ОС и архитектуры**. Для бинарных выпусков Python и pip
не нужны: интерпретатор и Tk включаются PyInstaller в файл приложения.

- Linux / SteamOS: `sh install.sh`, либо `./tthings-bin --install`.
- macOS: открыть `Install.command`, либо `sh install.sh`.
- Windows: открыть `Install.cmd`, либо `.\tthings-bin.exe --install`.

После установки: `tthings` в терминале. На Windows откройте новый терминал,
чтобы обновился пользовательский PATH. На Linux/macOS команда устанавливается
в `~/.local/bin`; если эта папка отсутствует в PATH, запускайте `~/.local/bin/tthings`.
На macOS также создаётся `~/Applications/tthings.command`.

**Сейчас подготовлены исходники, zipapp и локальная Linux-сборка. Windows/macOS
бинарники ещё не собраны и не проверены.** Workflow `Portable builds` собирает
отдельные архивы для Linux x86_64, Windows x86_64, macOS Intel и macOS Apple Silicon.
Это подготовленная конфигурация CI, а не уже опубликованные релизы.

Локальная Linux-сборка сделана на SteamOS с новой glibc, поэтому она не является
универсальным бинарником для старых дистрибутивов. Workflow для Linux использует
Ubuntu 22.04; минимальная совместимость такого выпуска — glibc 2.35 и необходимые
графические библиотеки для оконного режима. Для других Linux есть исходный zipapp.
Alpine/musl, Windows ARM, старые ОС и Android/Termux в этот выпуск не входят.
Невозможно обещать один исполняемый файл для любого Linux и всех трёх ОС.

## Управление

| Клавиша | Действие |
|---|---|
| ↑ / ↓, J / K | Выбрать эффект |
| Enter | Запустить |
| 2 / F2 / `/` | Поиск; Enter завершает ввод, Esc возвращает к списку |
| 1 | Beautiful Things — встроенные эффекты |
| 4 | Systems Things — мониторинг и полезные инструменты |
| ← / → | Переключить вкладку |
| 3 | Каталог оригинальных проектов |
| Tab | Следующая категория |
| `*` | Добавить или убрать избранное |
| F | Показывать избранное |
| R | Случайная встроенная анимация из текущего списка |
| W | Выбранная встроенная анимация в отдельном окне |
| G | Выделить область мышью и открыть случайную анимацию |
| P | Сменить палитру |
| O | Открыть страницу оригинального проекта |
| Esc / Q | Назад / выход |

Во время анимации: **Space** — пауза, **R** — случайная,
**N** — следующая по списку, **P** — цвет, **H** — панель подсказок (терминал), **Esc** — закрыть.
**Удержание R около 2 секунд** включает/выключает автопоказ. Каждый новый интервал
выбирается случайно от **30 до 130 секунд**. **A** и кнопка «Авто» — альтернативы.
Пауза Space также останавливает таймер автопоказа. В обычном терминале удержание
распознаётся по автоповтору клавиши; при отключённом автоповторе используйте A.
В окне есть кнопки «Далее», «Случайный», «Авто»; кнопку «Случайный» тоже можно
держать две секунды. Буквенные N/R/P/A поддерживают русскую раскладку.
Размер эффекта пересчитывается при изменении окна. В оконном режиме есть меню
правой кнопки мыши. Окно рисует тот же символьный кадр, что и терминал;
это отдельное графическое окно, а не управление чужим эмулятором терминала.

## Область и глобальная комбинация клавиш

```sh
tthings --region
```

На SteamOS/Linux выделение использует прозрачные нативные окна Qt 6:
рабочий стол и открытые приложения остаются видны, рисуется только контур.
Чёрная подложка, затемнение и снимок экрана не используются.
Qt 6 QML runtime уже входит в KDE на этой SteamOS. На других Linux его наличие
требуется отдельно для выделения; можно указать путь через `TTHINGS_QML`.
Терминальные эффекты и обычные окна не требуют Qt.

Затем протяните прямоугольник мышью. **Esc** отменяет выбор. При слишком маленьком
прямоугольнике выделите больший. В выбранной области откроется окно случайной
встроенной анимации. На Linux выделитель создаёт прозрачную поверхность на каждом экране Qt;
мультимониторные конфигурации и разные DPI требуют проверки на конкретной ОС.

Установщик готовит глобальное сочетание:

- **KDE / SteamOS Desktop:** `Meta+Alt+G`, через собственный сервис KGlobalAccel.
  Возможно, потребуется выйти и войти в графический сеанс. Если сочетание занято,
  измените его в «Параметры системы → Клавиатура → Комбинации клавиш → tthings — область».
- **Windows:** `Win+Alt+G`; обработчик добавляется в автозагрузку текущего пользователя.
- **macOS:** `Cmd+Option+G`; обработчик добавляется в пользовательский LaunchAgent.
- **Linux X11:** `Meta+Alt+G`; обработчик в пользовательской автозагрузке.
- **Другие Wayland-композиторы:** назначьте `tthings --region` в настройках своего
  рабочего стола. Приложение не может перехватывать глобальные клавиши произвольно.

На Windows/macOS/X11 обработчик запускается при следующем входе;
для текущего сеанса можно запустить `tthings --hotkey`.
Повторная подготовка: `tthings --enable-hotkey`.

Прозрачность слоя Qt и рамки проверены рендерингом offscreen: альфа фона и
внутри рамки — 0, контура — 255. Проверены координаты выделения в обратную сторону.
Графический сеанс этой среды недоступен из sandbox, поэтому живое выделение,
позиционирование, глобальные сочетания и оконный resize **не проверены на живом
рабочем столе**. Они реализованы, но требуют проверки на целевых системах.

## Привязка к существующим окнам (0.2.0)

- **Meta+Alt+G** — свободное выделение, как раньше.
- **Ctrl+Meta+Alt+G** — выделение с привязкой. Ctrl нужен при запуске;
  после запуска его можно отпустить. На macOS: Ctrl+Cmd+Option+G.
- Командный эквивалент: `tthings --region --snap`.

В магнитном режиме контур золотистый. Оба угла рамки притягиваются к
ближайшим сторонам видимых окон на расстоянии до **14 логических пикселей**.
Привязка учитывает длину стороны: продолжение линии далеко за пределами
окна не притягивает курсор. Поддерживаются отрицательные координаты мониторов.
Границы фиксируются перед выделением; существующие окна не перемещаются.

На SteamOS/KDE границы получаются через временный read-only скрипт KWin
и D-Bus-приёмник на системных GLib/GIO, без Python-зависимостей. Свёрнутые окна,
другие рабочие столы, обои и панели отфильтрованы. Скрипт выгружается после
получения геометрии. Окна эффектов tthings дополнительно публикуют свою геометрию
в пользовательском кэше; записи проверяются на живой процесс и актуальность.
Ни названия окон, ни снимки экрана не сохраняются.

Также реализованы источники границ Windows и macOS; они не проверены на этих ОС.
Другие X11-сеансы используют wmctrl, если он установлен. Другие Wayland-композиторы
пока не предоставляют этому приложению границы окон.

Окно, созданное по выделению, не имеет заголовка, чтобы его границы совпадали
с выбранной рамкой. **Shift+ЛКМ** — переместить, **Shift+ПКМ** — изменить размер,
**ПКМ** — меню, **Esc** — закрыть.
После обновления сочетаний KDE может потребоваться повторный вход в сеанс.

Проверен алгоритм привязки на Python и в настоящем движке Qt/QML offscreen.
Живые границы KWin и глобальные сочетания в этой sandbox-среде проверить нельзя:
доступ к сеансовому D-Bus запрещён. Проверка на рабочем столе остаётся необходимой.

## Что входит автономно

200 собственных процедурных эффектов: бонсай, сакура, аквариум, снег, дождь,
лава, потоки частиц из точек Брайля, плазма, огонь, фейерверк, «Жизнь», трубы,
матрица, звёздный полёт, глобус, часы, 3D-пончик, DVD, декоративный спектр.
Добавлены сияние, галактика, чёрная дыра, океан, круги на воде, туннель,
ландшафт, ДНК, Лиссажу, Лоренц, маятники, калейдоскоп, молнии, пузырьки,
светлячки, орбиты, радар, стая, лабиринт, Мандельброт, Жюлиа, кольца,
полярная роза и радужные арки.
Они не скачивают данные и работают без сторонних команд.

Это собственные реализации мотивов, **не копии всех перечисленных проектов**.
Глобус использует грубые условные контуры, а не NASA/OpenStreetMap.
Спектр помечен «демо»: он не анализирует звук. Реальное аудио доступно через
внешний CAVA; подробная интерактивная карта — через внешний MapSCII и другие.

В каталоге дополнительно собран 41 внешний проект (включая btop, ncdu, duf, dust,
gdu, fastfetch и calcurse). btop и ncdu уже доступны на текущей SteamOS.
У ncdu запуск настроен в режиме только просмотра (-r).
Лаунчер запускает установленный инструмент и возвращается в меню после его выхода.
Статус `+` означает найденный исполняемый файл, `↗` — ссылку на проект.
Внешние программы **не включены в бинарник, не устанавливаются автоматически,
могут иметь зависимости и платформенные ограничения**. Объединение всех их исходников
и лицензий в один переносимый бинарник в этом прототипе не выполнено.

Для переносимых внешних программ лаунчер ищет исполняемые файлы в:

1. `$TTHINGS_TOOLS/<id>/bin` и `$TTHINGS_TOOLS/<id>`;
2. по умолчанию `~/.local/share/tthings/tools/<id>/bin` и `<id>`;
3. `~/.local/bin`;
4. системном PATH.

На Windows поддерживается суффикс `.exe`. Скрипты внешних проектов могут требовать
свой интерпретатор. Для сборников без стабильной команды предусмотрена ссылка.
Внешние проекты остаются под собственными лицензиями; их код не поставляется.

## Systems Things (0.3.0)

Вкладка **4**: 12 встроенных инструментов, отдельные от Beautiful Things.
Они не участвуют в случайном выборе эффектов и не открываются как случайные заставки.

- Производительность: реальная загрузка CPU/ядер, RAM, swap, load, uptime,
  температуры и GPU/VRAM, если драйвер предоставляет sysfs-счётчики.
- Состояние сети: интерфейсы, линк, приём/передача, накопленные байты, ошибки, потери.
  Это состояние интерфейсов; внешние проверки интернета не выполняются.
- Нагрузка дисков: чтение/запись в секунду, IOPS, время активности устройства.
- Место на дисках: занято, свободно, ёмкость и полосы заполнения.
- Что занимает место: сканер папки с размерами её дочерних элементов на диске.
  Нет удаления. Не переходит по symlink и другим файловым системам; hardlink
  считается один раз. Esc отменяет сканирование. По умолчанию сканируется HOME.
- Процессы: CPU и RAM, с сортировкой по CPU; аргументы команд не показываются.
- Календарь: месяцы, вид года, сегодняшняя дата. ←/→ месяц, Y год, T сегодня.
- О системе: ОС, архитектура, CPU, терминал и графический сеанс.
- Датчики и батарея; секундомер с кругами; мировые часы; просмотр журналов.

У мониторинга производительности, сети, нагрузки дисков и места на дисках
есть **четыре раздельных JSONL-журнала**. Запись включена при открытии этих панелей,
**L** её останавливает/возобновляет. Вне панели фонового журналирования нет.
Каждый файл ограничен 5 MiB + три ротации (до 20 MiB на вид журнала).
Системные счётчики обновляются раз в секунду, место на дисках — раз в 10 секунд.
Первый расчёт скоростей требует двух замеров; недоступные значения показаны «—».

Пути журналов:
- Linux: `$XDG_STATE_HOME/tthings/journals` или `~/.local/state/tthings/journals`.
- macOS: `~/Library/Logs/tthings`.
- Windows: `%LOCALAPPDATA%/tthings/logs`.

В журнал не пишутся пакеты, адреса соединений, аргументы процессов или файлы сканера.
В разделе «Журналы» Tab переключает четыре файла; ↑↓ листают последние 100 записей.
Timestamp в журналах — UTC.

Linux использует /proc и /sys без sudo, без сторонних Python-модулей.
В sandbox/network namespace часть интерфейсов и процессов может быть скрыта;
это не имитация данных и не основание подставлять нулевые значения.
На macOS/Windows мониторинг требует psutil, который устанавливается в CI сборки
и включается в соответствующий бинарник; эти ветки на живых ОС не проверены.
Для запуска исходников на этих ОС: установить зависимости из pyproject.toml.
Windows для мировых часов также требует tzdata, включаемую в готовую сборку.

Прямой запуск:

```sh
tthings --tool performance
tthings --tool network
tthings --tool disk-io
tthings --tool disk-space
tthings --tool storage --path ~/Downloads
tthings --tool calendar
tthings --tool journals
```

JSON без терминала (один замер с интервалом около секунды, без записи журнала):

```sh
tthings --tool performance --once
tthings --tool network --once
tthings --tool disk-io --once
```

В `--list --json` теперь есть поле `kind`: `effect`, `tool`, `external`.
Запускать `kind=tool` через `--tool ID`, а эффекты — через `--effect ID`.
Поле builtin=true само по себе больше не означает анимацию.

tthings --random

## История разработки

Ниже сохранены ранние записи автора о последовательных итерациях. Их промежуточные числа не описывают текущий каталог; актуальное количество указано в начале файла.

### Автономность, логотипы и подпись вкладки

В ранней итерации было 130 встроенных анимаций: добавлены 69 сцен — туманности, пульсар,
комета, метеоры, Сатурн, червоточина, Луна, затмение, облака, водопад,
листья, медузы, бабочки, цветы, кораллы, песок, фонтан, искры, магнитное поле,
дым, течение, взрыв, куб, тессеракт, сфера, тороидальный узел, Мёбиус, Клейн,
спирограф, муар, квазикристалл, фракталы и ретро-сцены. Новые эффекты доступны
из меню, через --effect, N/R и в автопоказе 30–130 секунд.

Вкладка терминала получает заголовок `tthings — название эффекта/инструмента`
через стандартный OSC 0. Заголовок обновляется при N/R, автопоказе и переходе
между инструментами. Терминал/встраивающий лаунчер должен поддерживать OSC title.
В конце восстанавливается title stack терминала, если он поддерживается.

Системные экраны имеют крупные блоковые/точечные/контурные/брайлевые цифры.
F меняет стиль, +/− размер; настройки сохраняются для каждого инструмента.

**«О системе» полностью автономно: fastfetch больше не запускается и не требуется.**
В пакет включён JSON-каталог 541 логотипа (MIT, источник — библиотека fastfetch).
Это статический ресурс, не исполняемый файл. Универсальный 3D-рендерер строит
объём из выбранного логотипа. При старте определяется реальная ОС:
- Windows: Windows-логотип, с учётом доступного номера сборки;
- macOS: macOS/Apple;
- Linux: ID/NAME из /etc/os-release и /usr/lib/os-release, затем ID_LIKE;
- неизвестный Linux: нейтральный Linux/Tux, **никогда не SteamOS по умолчанию**.

Данные Linux читаются из /proc и /sys, Windows — через реестр и WinAPI,
macOS — через libSystem/sysctl; psutil входит в соответствующие бинарные сборки.
Никаких shell-команд для «О системе», скачиваний и пользовательских установок.
На исходниках Python-пакеты из pyproject.toml нужны только разработчику;
конечному пользователю поставляется соответствующий его ОС бинарник.

Логотип теперь имеет плотный объёмный рендер на уровне подъячеек терминала,
занимает ограниченную область и выровнен верхом с заголовком сводки.
Длинные ключи и значения переносятся в своих колонках. Размеры дисков —
настоящие used/total, повторные точки монтирования одного источника убраны.

Полная библиотека и выбор логотипов проверены для Windows/macOS/Arch/Gentoo/
SteamOS и других Linux; это проверка ресурсов/выбора, не запуск всех этих ОС.
Нативные Windows/macOS сборки и их API по-прежнему требуют живой проверки.
Источник/лицензии каталога: THIRD_PARTY_NOTICES.md, licenses/fastfetch-LICENSE.

## Systems Things 0.7.2

19 инструментов. Новые: Помодоро (25/5), обратный таймер, прогресс даты,
Unix-время, лаборатория цвета, коды клавиш, калькулятор и конвертер единиц.
Калькулятор: Enter результат, Tab вставляет sqrt/sin/cos/log/abs, Backspace
удаляет символ. Конвертер: Tab режим, ввод числа и Backspace. Таймер: Space
старт/пауза, ←→ минуты на паузе, Backspace сброс. Время отсчитывается только
в текущей запущенной сессии, фонового сервиса после выхода нет.

R случайный инструмент, удержание R около двух секунд включает/выключает
автосмену каждые случайные 30–120 секунд, A переключает авто одним нажатием.
N следующий. Удержание в терминале определяется по повторам клавиатуры.
Открыть случайный инструмент можно и из меню Systems Things по R.
Состояние автоцикла, палитра, таймер и Помодоро сохраняются между инструментами
до выхода в главное меню.

Подписи кнопок зависят от экрана: F показывает «шрифт цифр», «шрифт даты»
или «вид логотипа». На процессах и других текстовых экранах этой настройки
нет. Размер цифр теперь выбирается по доступному месту автоматически;
бесполезные +/- и прежняя подпись «[ / ] инструмент» убраны.
Идеи таймеров изучены по [Pomotroid](https://github.com/Splode/pomotroid)
и [timer](https://github.com/caarlos0/timer); реализации собственные,
устанавливать эти программы не требуется.

## 0.7.2 — подписи вкладок Konsole

Заголовок эффекта: tthings — Часы (clock) · Beautiful Things.
Заголовок инструмента: tthings — Процессы · Systems Things. Подпись меняется
при N/R, автоцикле и переходе в меню. В Konsole OSC30 временно переводит
формат текущей вкладки на %w, затем OSC0 задаёт текущую функцию. При выходе
восстанавливается формат из сессии (если доступен qdbus), иначе из профиля
по умолчанию, а без него стандартный %d : %n. Файлы профилей не меняются.
Остальные терминалы получают OSC0. Tk-окна используют ту же подпись.
См. [форматы вкладок KDE](https://docs.kde.org/stable_kf6/en/konsole/konsole/console-dialogs.html)
и [обработку OSC30 в Konsole](https://github.com/KDE/konsole/blob/master/src/session/Session.cpp).
